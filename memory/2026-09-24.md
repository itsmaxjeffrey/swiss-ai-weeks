Owner asked to try a real browser against the walls. Tried all three routes:
- Standalone `google-chrome --headless=new --dump-dom`: broken on this host even
  for example.com (40-byte empty DOM, zero stderr) — environmental, not site-side.
- OpenClaw managed browser (real headless Chrome, CDP, profile `openclaw`):
  works fine on normal sites, but digitec.ch RSTs at HTTP/2

(server-side RST) — client-side tricks don't apply; datacenter IP reputation
also plays in. Agent instructions updated (commit `b88d485`): don't retry walled
shops via browser more than once, report bot-walled, offer registry
corroboration instead. Zefix needs a free registered API token (401 without) —
flagged as follow-up for the LEASH-native verification path.
