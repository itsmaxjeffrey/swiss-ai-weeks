### Stop button that actually stops the agent, 02:05–02:50 (project: github-swiss-ai-weeks/itsmaxjeffrey/swiss-ai-weeks)
- Owner ask: stop button for the chat that stops the AI from working. Finding: a stop button existed (`bfb8cdf` — header "stop" label + `/api/chat/stop`) but it NEVER actually stopped the agent: it SIGKILLed the bridge's direct child, which is just the `openclaw` launcher; the real CLI runs as an anchored grandchild in a supervisor-owned process group and kept working (proof: activity frames 4+ min after stop; the interrupted run completed at 560.9s with a full reply that silently landed in session history).
- Failed approaches (all live-tested): v2 "stop" chat message to the session = queues a PHANTOM turn, never aborts CLI-spawned runs (the docs' abort phrases apply to inbound channel messages); `chat.abort {sessionKey}` / `sessions.abort` RPCs = "unauthorized" for runs the caller connection didn't start (vacuous `{ok,runIds:[]}` when idle); process-group kill (`detached:true` + `kill(-pid)`) = misses the anchored grandchild; exitCode-alive backstop = skipped because the launcher's exitCode is already set while the run streams.
- v4 that WORKS (`846e321`): agentTurn injects unique `VISECA_TURN_TOKEN` env into the CLI spawn; `/api/chat/stop` scans `/proc/*/environ` for the token and SIGKILLs every match (reaches the anchored grandchild wherever the supervisor parked it) + 12s group-kill backstop. Also: turnWithRetry skips the continuation retry when stopped (a stop-abort looks exactly like no-reply — without the guard the AI would RESTART after stop); stop button moved from the tiny header label into the composer as a send↔stop morph (`.composer.busy` needs a pointer-events override for it).
- Verified per deploy: node --check, 57/57 smoke, boot marker in journal, live E2E (fresh account, stop at 10s → `killed CLI pids: 211924,211932`, turn FAILED 10.0s logged, SSE terminal "Stopped —" frame at 15.1s, zero post-stop activity). Service deploys via `systemctl --user restart viseca-shopper-ui` (user unit since ~01:44 — the setsid nohup recipe is dead for this app).

### wallet-control: Trusted Shops merchant verification feature (03:13–04:0x) (project: github-swiss-ai-weeks/itsmaxjeffrey/swiss-ai-weeks)
- Owner ask: wallet-control should automatically + concurrently check whether merchant websites the agent suggests are listed on Trusted Shops (any country domain). Shipped in commit `5433521`; 14 new hermetic tests (55 total), live-verified.
- **Trusted Shops public API (verified live, no key):** `GET https://api.trustedshops.com/rest/public/v2/shops.json?url=<bare-hostname>` → 200 `{response.data.shops:[{tsId,url,name,languageISO2,targetMarketISO3}]}` or 404 `SHOP_URL_NOT_FOUND` (= genuinely not registered — digitec.ch, brack.ch, landi.ch, galaxus are NOT TS members; conrad.de IS, conrad.ch is NOT: registration is per registered domain). `GET .../shops/{tsId}/quality.json` → `qualityIndicators.reviewIndicator` (overallMark 4.79 "EXCELLENT", totalReviewCount 1703, reviewsCountedSince). ONE global registry behind all country sites (.com/.de/.ch/…) — `targetMarketISO3` (CHE/DEU/AUT/EUO…) says which market a registration is certified for; suffix matching means `m-s-v.eu` finds `www.m-s-v.eu` entries. Latency ~150 ms/call via egress proxy. Dead ends: legacy profile URL patterns `bewertung/info_{tsId}.html` + `certificate_{tsId}.html` both 404 now; there is NO public name-search endpoint (only url lookup); the shop-search SPA (shop-search-cdn.trustedshops.de, Next.js) hides its API and server-renders nothing for `?searchWords=`.
- **Implementation:** `lib/trustedshops.js` — `TrustedShopsChecker` class: 8-way concurrency pool, 4 s per-request deadline, 6 h TTL cache, in-flight dedupe, injectable `fetchImpl` for hermetic tests. Agent-facing: `POST /api/trustedshops/check {merchants:[…]}` + `GET ?merchant=`; measured 5 merchants ≈ 305 ms. Automatic path: worker pre-fetches the check for any merchant event carrying a website (1.2 s race cap, never risks the 8 s platform deadline; late results land in cache for later events) and passes `extras.trustedShops` into `evaluate()` (new optional 5th arg, engine 1.2.0). Advisory only by design: listed → evidence line + `TRUSTEDSHOPS_LISTED` positive flag; not-listed → neutral evidence (absence ≠ guilt); failed check → silent. Name-only merchants answered honestly (`no domain supplied`) — never invent domains.
- **Node lesson (bit hard):** `AbortSignal.timeout()` never keeps the event loop alive by design — with a pure-hang fetch, the loop drains and Node exits (unsettled top-level await, exit 13) BEFORE the abort fires. Timeout wrappers must enforce their own ref'ed `setTimeout` via `Promise.race` (keep the signal too, to abort real sockets).
- Test-count gotcha: a listed check makes 2 HTTP calls (lookup + quality) — assert on lookup-count, not total calls. `npm test` order matters: trustedshops suite runs last in package.json.
